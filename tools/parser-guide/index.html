    3. Las reglas del .bru

    El parser no usa expresiones regulares ni una gramática generada. Es un cursor (pos) que avanza por el texto y mira lo que tiene delante. Estas son todas las decisiones que toma; cada tarjeta tiene un botón para probarla en el playground.

    El cursor

    Toda la clase Parser gira alrededor de un índice pos sobre el texto (con los \r\n ya convertidos a \n). Estas funciones lo leen o lo mueven:

    url: http://localhost
    pos está en ":" · rest_of_line() es lo azul
    rest()todo desde pos
    rest_of_line()desde pos hasta el salto de línea
    take_line()devuelve lo anterior y salta a la línea siguiente
    eat("x")si lo siguiente es x, lo consume y devuelve true
    skip_spaces()consume espacios y tabuladores
    line()cuenta los \n antes de pos (para errores)

    ¿Qué es cada cabecera?

    Fuera de un bloque, block() lee la línea entera, le hace trim y la clasifica en este orden:

    1. Termina en {} → bloque vacío
    2. Termina en { → bloque con llaves (texto o diccionario, ver siguiente tarjeta)
    3. Termina en [ → array en varias líneas
    4. Tiene [ y termina en ] → array en una línea
    5. Tiene : → valor inline (color: #fff)
    6. Nada de lo anterior → expected a block

    El nombre no puede tener espacios: my block { es invalid block name.

    ¿Texto o diccionario?

    Lo decide el nombre, no el contenido (braces_block):

    • Texto: body, body:json|text|xml|sparql|graphql|graphql:vars, tests, docs, example y todo script:*.
    • Diccionario: meta, métodos HTTP, headers, params:*, vars:*, assert, auth, auth:*, formularios, settings…
    • Desconocido: se intenta como diccionario; si falla, se vuelve atrás (self.pos = start) y se lee como texto. En la traza verás los pasos descartados tachados.

    ¿Dónde acaba un bloque?

    En una línea que es exactamente } en la columna 0 (se permiten espacios detrás). Por eso un JSON dentro de body:json no cierra el bloque: sus } van indentados.

    body:json {
  {
    "a": 1
  }        ← indentada: es texto
}          ← columna 0: fin

    En un diccionario, si aparece otra cabecera como get { en la columna 0, se informa de que el bloque anterior no se cerró en vez de dar un error confuso.

    Texto: indentación

    text() junta las líneas hasta el }:

    • Se saltan las líneas vacías del principio.
    • A cada línea se le quitan exactamente 2 espacios si los tiene (los que añade Bruno al guardar). El resto de indentación se conserva.
    • Las líneas vacías del final sí se conservan.

    Claves

    • Normal: hasta :, espacio o tabulador. url: x
    • Entre comillas: permite :, espacios y llaves, con \" como escape. "colon:key": x
    • ~ delante: el par existe pero está deshabilitado (enabled: false). Vale para las dos formas: ~key y ~"key".
    • En assert: la clave llega hasta el : e incluye espacios: res.body.items.length : gt 2.

    Si después de la clave no hay : → expected `:` after the key.

    Valores

    Tras el : se mira lo que viene:

    1. Solo [ → lista: un elemento por línea hasta ].
    2. Empieza por ''' → multilínea hasta el siguiente '''. Se quitan hasta 4 espacios por línea y luego trim. Detrás solo se admite @contentType(...), que se pega al valor.
    3. Cualquier otra cosa → resto de la línea con trim. Puede ser vacío.

    Anotaciones vs claves con @

    Una línea que empieza por @ puede ser dos cosas:

    • Anotación: @nombre o @nombre(argumento) y nada más en la línea. Se guarda y se asigna al siguiente par.
    • Clave: si tras el nombre hay : u otro texto, annotation() devuelve None, restaura pos y se lee como par. Así funciona @orderNumber: … (variable local).

    El argumento puede ir con '…', "…" (con escapes \n \t \" \\), '''…''' (multilínea) o sin comillas.

    Errores

    unclosed block `x`fin de fichero u otra cabecera antes del }. La línea es la de la cabecera.
    expected `:` after the keyun par sin dos puntos
    expected a keyuna línea que empieza por :
    unclosed quoted keyfalta la " de cierre en la misma línea
    unclosed listllega el } antes del ]
    unclosed multiline valueno hay ''' de cierre
    expected a blocktexto suelto fuera de un bloque

    Nunca hay panic: todo devuelve Result<_, ParseError>.

    bru.rs produce bloques genéricos. bru2struct.rs busca los bloques por nombre y rellena el modelo. yml2struct.rs hace lo mismo con las claves del YAML de OpenCollection. Los valores por defecto son los de Bruno.

    5. Colección y orden

    collection::load sube desde la ruta hasta encontrar opencollection.yml (YAML) o bruno.json (bru). Si no encuentra ninguno, trata la carpeta como ficheros sueltos. Después recorre el árbol:

    Qué se salta

    • collection.* y folder.*: no son peticiones, son los valores por defecto (Defaults).
    • environments/ en la raíz: se leen aparte como Environment.
    • Cualquier segmento node_modules o .git.
    • Rutas del ignore: iguales a la ruta relativa, o prefijo de carpeta (skipped ignora skipped/a.bru).
    • Ficheros del otro formato y enlaces simbólicos a carpetas.

    En qué orden se ejecuta

    En cada carpeta: primero las subcarpetas (recorridas enteras), luego las peticiones por seq. Los ficheros que no se pueden parsear van al final.

    Las carpetas usan sortByNameThenSequence de Bruno: orden alfabético, y después cada carpeta con un seq válido (entero ≥ 1) se inserta en la posición seq − 1. Si ya hay otra con el mismo seq, se agrupan.

    Prueba el orden de carpetas

    Una carpeta por línea: nombre seq (el seq es opcional).

      6. ¿Me puedo fiar de esta página?

      parser.js es una traducción línea a línea de bru.rs y bru2struct.rs, con la traza añadida. Para que no se desincronice hay una prueba diferencial: un pequeño crate (tools/parser-guide/difftest) compila los ficheros Rust reales con #[path], y se comparan las dos salidas en JSON sobre:

      • todos los .bru del repositorio,
      • casos límite escritos a mano (Unicode, CRLF, anotaciones, errores…),
      • 6000 mutaciones aleatorias de esos ficheros (líneas borradas, duplicadas, reindentadas, ''', }, ~ sueltos…).

      Se ejecuta con devenv shell parser-guide-check y debe acabar en mismatches=0. Si cambias el parser en Rust, cambia también parser.js.

      Lo que no está portado: yml2struct (necesitaría un parser YAML en el navegador) y el loader, aparte del algoritmo de orden de la sección 5.
